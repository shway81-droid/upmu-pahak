# 설정 파일 형식

세 파일 모두 `<공문 폴더>/_작업/` 에 UTF-8 JSON으로 둔다.

## tasks.json — 탭(부서)과 업무명 칩, 분류 규칙

```json
{
  "school": "○○초등학교",
  "school_short": "○○초",
  "groups": [
    {
      "label": "교무",
      "folders": ["교무부"],
      "drafters": ["김○○"],
      "tasks": [
        {"id": "G_hakpok", "name": "학교폭력 예방",
         "desc": "학교폭력 관련 업무, 교육활동 보호",
         "pattern": "학교폭력|학폭|평화교실|분리조치|전담기구|교육활동\\s*보호|교육활동\\s*침해"},
        {"id": "G_teuksu", "name": "특수교육",
         "desc": "특수교육과정 업무 전반, 장애이해 교육",
         "pattern": "특수|개별화|장애|통합교육|통합학급"},
        {"id": "G_insa", "name": "교감업무대행 · 교원인사",
         "desc": "성과상여금, 다면평가·근평, 승진가산점, 강사계약",

    },
    {
      "label": "돌봄",
      "folders": ["돌봄"],
      "drafters": ["박○○"],
      "tasks": [
        {"id": "C_gansik", "name": "간식 · 방학 중 중식", "desc": "간식·과일간식, 방학 중 도시락 위탁·점검", "pattern": "간식|과일|도시락|중식|위탁"},
```

- `label` — 탭에 보이는 이름. 짧게("교무", "연구", "정보과학체육").
- `folders` — 이 부서에 해당하는 **최상위 폴더명**(extract.py 출력의 "최상위 폴더별 본문 수"에 나온 그대로).
  폴더가 부서로 안 나뉘어 있으면 비워 두고 `drafters`로 묶는다. 둘 다 있으면 폴더가 우선한다.
- `drafters` — 업무분장표의 담당자 이름. extract.py 출력의 "기안자" 표기와 같아야 한다.
- `tasks[].id` — 영문·숫자·밑줄. 전체에서 유일해야 한다. `g0_etc` 꼴은 기타용으로 예약돼 있으니 쓰지 않는다.
- `tasks[].name` — 업무분장표의 업무명 그대로. `tasks[].desc` — 업무분장표의 업무 내용 원문(칩을 눌렀을 때 한 줄로 보인다).
- `tasks[].pattern` — 제목에 거는 정규식. **위에서부터 첫 매칭이 이긴다.** 맨 아래 업무에 `"."`을 주면 "나머지 전부"가 된다(업무 수가 적은 부서에 유용).
  JSON이므로 역슬래시는 두 번(`\\s`).
- 각 부서에는 자동으로 "공통 · 기타" 업무(`g<순번>_etc`)가 붙는다. 제목에 국회·도의회·의원·감사원·행정사무감사가 들어가면 규칙보다 먼저 기타로 간다
  (바꾸려면 최상위에 `"etc_pattern": "정규식"`).
- `tasks[].order` — (선택) 칩 **표시 순서**. 배열 순서는 분류 우선순위라서 포괄 업무가 맨 아래로 가는데, 화면에서는 업무분장표 순서대로 보이고 싶을 때 1, 2, 3…을 준다.
- `groups[].etc_pattern` — (선택) 그 부서에서만 기타로 보낼 제목 정규식. 예: `"가족체험학습|교외체험학습 보고서|좋은수업.*박○○"`.
- `groups[].color` — 생략하면 기본 팔레트에서 순서대로 배정된다.

## overrides.json — 규칙으로 안 되는 한두 건

```json
{"2025-2158": "G_gyomu", "2025-7895": "R_maeul", "2026-529": "G_gyomu"}
```
키는 문서 id(`결재연도-문서번호`, `classify.py --list` 출력과 `titles.txt` 맨 앞에 나온다). 값은 task id 또는 `g<순번>_etc`.
**다른 부서의 task id를 주면 문서가 그 부서 탭으로 옮겨진다** — 다른 부서 폴더에 들어가 있는 같은 사업 문서를 한곳에 모을 때 쓴다.

## notes.json — 업무별 1년 흐름과 핵심 문서

```json
{
  "G_hakpok": {
    "flow": "3월 근절대책 계획·담당자 현황·예방교육 신청 → 4월 1차 실태조사 안내 → 5~6월 교육활동 보호(민원대응 계획·점검표·연수) → 수시 예산 물품 구입 → 10월 학폭 유공 승진가산점 선정(인사자문위 → 선정위 1·2차 → 명단 제출) → 12월 전담기구 현황 → 1~2월 차년도 전담기구 학부모 위원 모집·학운위 추천",
    "key": ["2025-2142", "2025-8070", "2025-8254", "2026-528"]
  },
  "C_gansik": {
    "flow": "3월 과일간식 소요량 조사·간식 구입 → 매월 말 다음 달 간식 구입 → 매월 과일간식 공급확인서 제출 → 6월 여름방학 도시락 신청 → 7월 중식 위탁 계획(성립전 예산 → 업체 현장점검 → 도시락 구입 → 안전점검 결과 제출) → 11월 겨울방학 도시락 신청 → 12월 겨울 중식 위탁 계획·점검·구입 → 1월 운영 안내장·점검 결과 → 2월 차년도 과일간식 신청",
    "key": ["2025-3878", "2025-5308"]
  }
}
```

- 키는 task id. 문서가 있는 모든 업무에 `flow`가 있어야 verify.py를 통과한다(기타는 없어도 된다).
- `flow`는 괄호 **밖**의 `→`에서 단계로 끊긴다. 단계 앞의 `3월`, `5~6월`, `매월`, `매월 말`, `수시`, `연중`이 시기로 강조된다.
- `key`의 id는 반드시 그 업무에 배정된 문서여야 한다(분류를 바꾸면 verify.py가 알려 준다).
